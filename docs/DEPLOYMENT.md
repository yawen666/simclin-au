# SimClin AU deployment guide

This guide describes the current two-service Render deployment for SimClin AU 1.0:

```text
Browser -> Render Static Site (Vue 3) -> Render Web Service (FastAPI, one worker)
                                        -> DeepSeek API
                                        -> SQLite (WAL)
```

The included [`render.yaml`](../render.yaml) defines both services. Their stable names produce these default URLs:

- Frontend: `https://simclin-au-web.onrender.com`
- API: `https://simclin-au-api.onrender.com`

If either service is renamed, update `WEB_ORIGIN` on the API and `VITE_API_BASE_URL` on the web service before rebuilding.

## Before publishing the repository

1. Rotate any provider credential used during development. Never paste its replacement into Git, a frontend variable, an issue, test output or a screenshot.
2. Confirm that `server/.env`, `server/.venv`, `server/data/*.db`, SQLite WAL/SHM files, uploads, logs, `dist/` and test artifacts are not tracked. The root `.gitignore` excludes these paths.
3. Keep `server/.env.example` and `web/.env.production.example` as placeholder-only templates.
4. Enable GitHub Secret Scanning and Push Protection for a public repository.
5. Keep the educational/non-clinical disclaimer visible in the repository README.

## Current Render Blueprint

The checked-in Blueprint deliberately remains on `plan: free`. Render installs `server/requirements.txt`, then starts:

```bash
uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1
```

Keep `--workers 1`. SQLite writes and persistent evaluation state are durable within the database file, while the guards that prevent concurrent messages and duplicate in-process evaluations are held by one FastAPI process.

To deploy the current demo:

1. Push the repository to GitHub.
2. In Render, choose **New > Blueprint** and select it.
3. Review `render.yaml` and create the API and static-site services.
4. Enter `DEEPSEEK_API_KEY` in Render's secret field. It is marked `sync: false` and is not stored in Git.
5. Render generates `FACULTY_DEMO_ACCESS_CODE`. An administrator can view it from the API service's Environment page and share it only with authorised educators.
6. Wait for `/api/health` to pass, then open the frontend URL.

### API environment variables

| Variable | Hosted value / rule |
| --- | --- |
| `ENVIRONMENT` | `production` |
| `PYTHON_VERSION` | Python 3.12 as pinned in `render.yaml` |
| `HOST` | `0.0.0.0` |
| `PORT` | Supplied by Render; the Blueprint uses `10000` as its declared value |
| `DATABASE_PATH` | Free demo: `./data/simclin-au.db`; persistent pilot: `/var/data/simclin-au.db` |
| `JWT_SECRET` | Generate a unique value; the app rejects the development default in production |
| `FACULTY_DEMO_ACCESS_CODE` | Random value generated by Render; minimum 12 characters and required in production |
| `DEEPSEEK_API_KEY` | Render secret only |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` unless the provider changes |
| `DEEPSEEK_MODEL` | Current configured model name |
| `AI_PROVIDER` | `deepseek`; never use `mock` for a real trial |
| `AI_REQUESTS_PER_HOUR` | Per-client preview budget; defaults to `60` in the single API process |
| `WEB_ORIGIN` | Exact deployed frontend origin, or a comma-separated allowlist |
| `LOG_LEVEL` | `info` by default |

The static frontend receives only `VITE_API_BASE_URL` and `VITE_BASE_PATH`; it must never receive the model key.

## SQLite durability: decision required before a stable pilot

The current free web service has an ephemeral filesystem. Sessions, results, drafts, overrides and uploaded files can disappear after a restart, redeploy or instance recycle. Startup recovery can resume a `queued` or interrupted `running` evaluation only when the SQLite file itself survives; it cannot recover data erased with the free filesystem.

Therefore the current Blueprint is suitable only for short demonstrations. Before a stable or longitudinal internal pilot, obtain the user's explicit approval to:

1. change the API from Render Free to a paid Starter service;
2. attach a persistent disk mounted at `/var/data`;
3. set `DATABASE_PATH=/var/data/simclin-au.db`;
4. keep exactly one API instance and one Uvicorn worker;
5. establish a backup, restore test and retention procedure for the SQLite file and uploads.

Do not silently make this paid-infrastructure change. Once approved, update the Blueprint and verify the disk mount before collecting any student records. WAL works well for this single-instance architecture, but the database still needs access controls, encrypted transport/storage, backups and an agreed retention policy.

## Background evaluation behaviour during deploys

Ending a consultation persists `evaluation_status=queued` and returns HTTP 202. A running API changes the task to `running`, retries one transient provider error, and saves either the completed result or a retryable failure state. During graceful shutdown, an interrupted evaluation is returned to `queued`; on startup, the coordinator reclaims records left `queued` or `running` when no evaluation row exists.

This design prevents a page navigation or ordinary process restart from losing the work item, provided the SQLite file is on durable storage. Deployment health checks should validate `/api/health`, then a synthetic mock-provider environment should validate the complete API/SSE contract before any real-model smoke test.

## GitHub Pages product showcase

The public-facing introduction site is [`docs/index.html`](index.html). It is a static, bilingual page with screenshots of the synthetic student and faculty flows. The `Publish product site` workflow uploads the whole `docs/` directory to GitHub Pages after a push to `main` or `master`.

After the first successful workflow run, enable **Settings > Pages > GitHub Actions** if GitHub has not selected the workflow automatically. A project site will normally be available at:

```text
https://<github-username>.github.io/<repository-name>/
```

GitHub Pages shows the product story; Render hosts the interactive Vue application and Python API.

## Local production-like check

```bash
python3.12 -m venv server/.venv
server/.venv/bin/pip install -r server/requirements-dev.txt
npm install
npm --prefix web install
npm run build
ENVIRONMENT=production \
JWT_SECRET=replace-with-a-long-random-secret \
FACULTY_DEMO_ACCESS_CODE=replace-with-a-separate-long-access-code \
HOST=127.0.0.1 PORT=4100 \
WEB_ORIGIN=http://127.0.0.1:5173 \
DATABASE_PATH=./data/simclin-au-production-check.db \
server/.venv/bin/python -m uvicorn app.main:app --app-dir server --host 127.0.0.1 --port 4100 --workers 1
```

Use `server/.env` for local secrets and Render environment variables for hosted secrets. Never place a real key directly in a committed command or file.
